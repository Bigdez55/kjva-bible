# Tokenless Training Workspace

`training/` is the in-tree training pipeline for the Tokenless model
substrate. It is **identity-neutral**: it ships generic training, evaluation,
export, serving, and PEFT/Omni infrastructure with no domain-specific corpus,
prompts, or recipe baked in.

## Training backend — PyTorch in Docker (canonical)

The **canonical training backend is PyTorch** (`training/pt/`), run in a portable
Docker image (`training/docker/`) — CPU locally, CUDA on a cloud/GPU host with no code
change. MLX is **not** the training backend (Apple-Metal-only; it cannot run in a Linux
container or on a GPU). The XMIND C + GGUF **inference** runtime is unchanged: the
PyTorch model preserves the exact 74-tensor GGUF contract, so `pt/export.py` →
`safetensors_to_gguf.py` produces a GGUF that loads in XMIND unaltered.

```bash
# Pretrain (Docker; --gpus all on a CUDA host)
training/docker/run_train.sh smoke      # 300-iter CPU proof
training/docker/run_train.sh full       # 5000-iter pretrain
# PEFT fine-tune
python3 pt/train_peft.py --method lora --base-checkpoint runs/byte_v1_20m \
    --corpus corpus/eng_kjv_apocrypha_v1/corpus.txt
```

The MLX scripts under `scripts/` (`model.py`, `train_byte.py`, `train_peft.py`) are
retained as **reference** (the operator-math reference + historical record), not the
active training path. See `docs/TRAINING_REGIMEN_CANONICAL_2026-05-31.md`.

Training outputs produced under this tree (runs, exports, gated adapters) are
staged at the runtime's canonical paths in the same tree via
`scripts/wire_base.sh` and `scripts/wire_all.sh`. A consuming project drops
its own domain corpus into `corpus/<id>/corpus.txt` (plus optional metadata)
and trains from there.

## Canonical Command (byte-level pretraining)

```bash
python3 training/scripts/train_byte.py \
  --run-id byte_v1_20m \
  --corpus training/corpus/<your-corpus-id>/corpus.txt
```

PEFT fine-tuning over an already-promoted base model:

```bash
python3 training/scripts/train_peft.py \
  --method lora \
  --base-checkpoint training/bases/<BASE_NAME>/weights.safetensors \
  --corpus training/corpus/<your-corpus-id>/corpus.txt
```

## Stage trained artefacts into the runtime

```bash
# Pull weights + config + vocab from the latest run
./training/scripts/wire_base.sh --from-run training/runs/byte_v1_20m

# Discover members + wire promoted adapters into data/soul/<m>/.adapter
./training/scripts/wire_all.sh
```

## Corpus Slot

```text
corpus/
├── <your-corpus-id>/
│   ├── corpus.txt              consuming project provides
│   ├── verses.jsonl            optional, enables per-category/per-group benches
│   ├── byte_vocab.json         optional metadata
│   ├── manifest.json           optional metadata
│   └── tokens_byte_uint16.npy  generated by train_byte.py
└── programs/                   omni training program corpus
```

Default corpus id used throughout the scripts (override via `--corpus`):

- `domain_corpus_v1`

## Subdirectories

These directories ship with the template (empty + a README, except `peft/` and
`scripts/` which hold real code). Their runtime outputs are generated locally
and are mostly ignored by Git:

- `scripts/` — training, eval, export, serving, and wiring programs (the
  consolidated home for everything that used to live in two scripts dirs).
- `peft/` — Omni-PEFT OS modules: profiler, fingerprint, compiler, tournament,
  registry, conflict, router, deployment, model, plus 37 PEFT method
  implementations under `peft/{low_rank, additive, prompt, activation,
  selective, hybrid, structural, alignment}/`.
- `programs/` — omni training registry and runnable program configuration.
- `corpus/` — domain corpus + tokens cache + manifests.
- `runs/` — training checkpoints, configs, logs, evaluation metadata.
- `adapters/` — PEFT adapter staging (`staging/`) and gated output (`gated/`).
- `bases/` — promoted base models (`promote_base_model.py --name <NAME>`).
- `exports/` — portable model bundles for inference / GGUF conversion.
- `gguf/` — GGUF or edge export artefacts.
- `eval/` — benchmark reports per run.
- `tokenizer/` — SentencePiece BPE tokenizer files.
- `logs/` — local server and orchestration process logs.
- `signals/` — optional JSONL runtime signal capture.
- `manifests/` — workspace-level inventory and expected-output manifests.
- `tests/` — runtime verification tests for the training/serving stack.
- `sc/` — local SUPER C training reference artefacts.
- `trainer/` — compatibility placeholder for older local scripts; active
  source code is in `scripts/`.

## Canonical Runtime Paths (gitignored, populated by wire_base.sh)

After `wire_base.sh` runs, these appear at the top of this directory:

- `weights.safetensors`  ← staged base model
- `model_config.json`    ← architecture spec
- `byte_vocab.json`      ← byte tokenizer constants
- `adapters/<member>/adapter.safetensors`  ← per-member LoRA (gitignored)
- `.staged_from`         ← provenance breadcrumb (gitignored)

## Safety Rules

- Do not commit checkpoints, weights, token caches, logs, or local process state.
- Do not copy auth/session/cache data from global `.claude` or `.codex`.
